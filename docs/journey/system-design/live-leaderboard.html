Designing a Live Leaderboard

A tournament leaderboard needs to accept score corrections and show the latest standings to spectators. I would start with a single database and measure the read load before adding a cache.

Keep scoring and ranking consistent

Store each match result in PostgreSQL with a match ID and version. An update supplies the version it expects. In a transaction, reject stale versions and apply the score change once. Define tie-breaking rules and test them against ties and corrections.

Update connected clients

After a transaction commits, send an event telling viewers to refresh their standings. A reconnecting client fetches the latest snapshot. If missing a notification is unacceptable, write an outbox record in the scoring transaction and let a worker publish it with retries.

Measure before adding a cache

Track score submission latency, time from score commit to display, and database read load. If reads become expensive, cache a versioned standings snapshot and define how long viewers can tolerate stale results.
