Prompt Injection, in Plain English

When an AI reads a document, it can mistake a sentence in the document for something it was asked to do.

A simple example

Imagine asking an agent to summarize a web page. The page contains text that tells the agent to send an email. The page is there to be read, and the user asked for a summary. If the model treats that text as a new instruction, it may try to do something the user never requested. That’s prompt injection.

Direct injection comes from the message someone sends to the agent. Indirect injection comes from something the agent opens, such as a website, email, PDF, or image. A search result can be relevant to your question and still contain text the agent should ignore.

Why tool access matters

A chatbot might give a misleading answer. An agent with tools may also be able to read private files, change records, or send messages. What can actually go wrong depends on what the app lets the agent do. Saved memory can extend the problem into future sessions if the app keeps an instruction from an untrusted source.

The riskiest combination is an agent that can read untrusted content, access private information, and send information out. For a web summary, the agent only needs to read the page and return the summary.

What I’d build into the harness

  • Give it fewer tools. A web summarizer needs read access to the requested page. It does not need private mail or a send button.
  • Check actions in code. Validate tool inputs and permissions in the application before anything runs. Review sensitive outputs before sharing them.
  • Keep track of sources. Label where information came from and check what gets saved to long-term memory.
  • Put people in control of consequential actions. Show what will be sent or changed and ask for approval when the action requires it.

Filters can catch some suspicious content. Permissions enforced by the app still apply when a filter misses something or the model makes the wrong call.
