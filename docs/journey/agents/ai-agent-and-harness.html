Agents

AI Agents and Harnesses, in Plain English

What happens between asking an AI to do something and getting a result you can trust?

What is an AI agent?

My way of thinking about an AI agent is that you give it a goal, and it handles some of the back-and-forth you would otherwise do yourself. A language model helps choose the next step. The surrounding software gives it tools it can use, such as search, a calculator, or an image generator.

Imagine I ask for a simple apple-shaped logo. With a vague brief, I might get an image that misses the style I had in mind. If I gather a few references and explain what I like about them, the brief gets clearer. An agent can collect references, use them to guide an image generator, and check the draft against the brief. I can still review the result and decide what works.

React as you go, or plan ahead

The think–act–observe loop is a plain-language way to describe ReAct, short for reasoning and acting. Each tool result helps the agent decide what to do next. If its first search turns up mostly colorful references and I asked for a black-and-white mark, it can narrow the search. ReAct paper

With plan and execute, the agent writes down the main steps first. For the logo, it might collect references, generate two drafts, then review each at a small size. The two approaches can work together. Use a plan to organize the job and a short loop to adapt inside a step.

Keep track of the details that matter

As the conversation grows, the agent may compress older messages into a shorter summary. This is called context compaction. A summary can drop a small but important detail, such as “no text” or “use a transparent background.” Keep requirements like those in a short checklist the agent can refer back to.

A team of agents is another organizational choice. One can gather references while another reviews drafts against the brief. Give each a clear job and pass along the same checklist. Every handoff adds work, so I’d start with one agent and split the work when the roles are distinct.

What is the harness?

The harness is the software around the model that runs the workflow and enforces its rules. It manages context, makes tools available, checks requests before running them, and records what happened. Think of the agent as the system doing the job and the harness as the code that keeps the job on track.

What should the harness check?

  • Tool inputs. Check types and allowed values. If a tool expects an integer from one to four for the number of drafts, validate it before calling the tool.
  • Output format. If the app expects fields such as title and description, check that both are present and have the right types. Fix a harmless formatting issue when the meaning is clear. For missing information, ask the model to try again with a retry limit.
  • Untrusted content. Prompt injection happens when text in a request, web page, or tool result tries to steer the agent away from its task. Attempts to reveal hidden instructions are one example. Input and output filters can help, and the harness should also enforce permissions outside the model. OWASP guidance on prompt injection
  • What happened during the run. Record which tools ran, which failed, and when the agent stopped. Keep sensitive content out of routine logs. A trace gives you something concrete to inspect when the result looks wrong.

I’d start with one model, one or two tools, and a clear check for success. Add a longer plan, more memory, or a second agent when the simpler setup falls short. That’s what “less is more” means to me when building AI people can monitor and trust.
